# Cloudflare Browser CDP Proxy

A Cloudflare Worker that exposes Cloudflare Browser Rendering as a remote Chrome DevTools Protocol endpoint over WebSocket.

This project is intended for generic remote-CDP clients such as OpenClaw, Browserless-compatible tooling, or anything that expects standard CDP discovery via `/json/version` and then a real DevTools WebSocket.

## Requirements

- Cloudflare account with Browser Rendering enabled
- `CDP_SECRETS` configured as a Worker secret
- `wrangler` authenticated for local development and deploys

## What This Worker Does

- Authenticates requests with `?secret=<configured-secret>`
- Exposes discovery endpoints:
  - `GET /json/version?secret=...`
  - `GET /json/list?secret=...`
  - `GET /json?secret=...`
- Gives each configured secret one shared Cloudflare Browser Rendering session and proxies raw DevTools sockets to it
- Keeps targets available across client reconnects with a 10-minute Browser Rendering keep-alive
- Turns `Cloudflare.getLiveView` results into short-lived share links that redirect to Browser Run Live View without exposing its JWT to the agent runtime

## Quick Start

```bash
npm install
printf '%s' '["your-secret"]' | npx wrangler secret put CDP_SECRETS
npm run deploy
```

To configure multiple independent browsers, add each secret to the JSON array. Each secret selects its own browser; clients using the same secret share targets.

```bash
printf '%s' '["alice-secret","bob-secret"]' | npx wrangler secret put CDP_SECRETS
npm run deploy
```

## Local Development

`wrangler.jsonc` sets the browser binding to `"remote": true`, which is required for local `wrangler dev` to talk to a real Browser Rendering session.

```bash
echo 'CDP_SECRETS=["test-secret"]' > .dev.vars
npm run dev
```

For multiple local browsers, add more values:

```bash
echo 'CDP_SECRETS=["alice-secret","bob-secret"]' > .dev.vars
npm run dev
```

## Endpoints

| Endpoint | Description |
| --- | --- |
| `GET /` | Info endpoint |
| `WS /?secret=<configured-secret>` | Raw DevTools WebSocket |
| `GET /json/version?secret=<configured-secret>` | Browserless-style CDP discovery |
| `GET /json/list?secret=<configured-secret>` | Discovery-compatible placeholder target listing |
| `GET /json?secret=<configured-secret>` | Alias for `/json/list` |
| `GET /handoff/<token>` | Short-lived redirect generated by `Cloudflare.getLiveView` |

## OpenClaw Example

OpenClaw supports both HTTP CDP discovery and direct WebSocket CDP URLs. For this Worker, prefer the direct WebSocket URL so OpenClaw talks straight to the proxied DevTools session:

```json
{
  "browser": {
    "enabled": true,
    "defaultProfile": "cloudflare",
    "remoteCdpTimeoutMs": 10000,
    "remoteCdpHandshakeTimeoutMs": 20000,
    "profiles": {
      "cloudflare": {
        "cdpUrl": "wss://your-worker.workers.dev/?secret=<configured-secret>"
      }
    }
  }
}
```

Notes:

- If you prefer the Browserless-style discovery path, `https://your-worker.workers.dev/?secret=<configured-secret>` also works for `/json/version`.
- The default OpenClaw examples for Browserless use much smaller timeouts. Cloudflare Browser Rendering cold starts can be slower, so higher OpenClaw timeouts are safer.
- This Worker is a session proxy, not a full Browserless replacement with stable `/json/list`, `/json/new`, and `/json/close/*` tab-management semantics.

## Human in the Loop

The proxy forwards Browser Run's `Cloudflare.*` CDP commands and events, including structured human handoff. For `Cloudflare.getLiveView`, it replaces the raw JWT-bearing URL with a short-lived Worker link that redirects the user to the same Live View. The agent can therefore share the returned `devtoolsFrontendUrl` directly.

Hermes Agent, OpenClaw, and similar Agent Skills-compatible apps can use the included [Cloudflare Browser Handoff skill](skills/cloudflare-browser-handoff/SKILL.md) to recognize takeover requests and run the handoff flow. The app must expose arbitrary raw CDP commands; Hermes provides `browser_cdp`, while OpenClaw requires a raw-CDP tool or plugin in addition to its high-level browser actions.

Run the interactive remote check against a deployed Worker:

```bash
CDP_URL='wss://your-worker.workers.dev/?secret=<configured-secret>' \
HANDOFF_URL=https://example.com \
HANDOFF_INSTRUCTIONS='Interact with the page, then select Done.' \
node scripts/test-handoff.js
```

Open the printed Live View URL, complete the task, and select **Done**. The script checks the completion event, inactive handoff state, and resumed CDP automation. `npm test` separately drives `Cloudflare.getLiveView` through the proxy and follows the generated redirect to verify the relay contract.

The Live View URL is a short-lived bearer credential: share it only with the intended operator and do not log or store it. Disconnecting closes only that CDP socket; reconnect with the same secret to resume the shared browser while its keep-alive remains active. See Cloudflare's [Human in the Loop documentation](https://developers.cloudflare.com/browser-run/features/human-in-the-loop/).

## Verification

```bash
npm test
npm run typecheck
```

If you want to smoke-test the deployed endpoint manually:

```bash
curl "https://your-worker.workers.dev/json/version?secret=<configured-secret>"
CDP_URL='wss://your-worker.workers.dev/?secret=<configured-secret>' node scripts/test-browser.js
```

The discovery response preserves the complete query string in `webSocketDebuggerUrl`. `CDP_URL` is passed to the test client unchanged and is not printed. The smoke test disconnects and reconnects, then proves the same target and DOM remain available.

## Security

- A value from the required, non-empty `CDP_SECRETS` array is required for all discovery and WebSocket endpoints.
- Treat the Worker URL plus secret as a remote browser credential.
- Treat generated `/handoff/<token>` URLs as short-lived bearer links and share them only with the intended operator.
- Everyone sharing one secret controls the same browser and can see its targets.
- Prefer deploying behind an unguessable secret and rotating it if it leaks.
